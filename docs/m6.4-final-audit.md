## 5. Dashboard defect found and fixed (not a documentation-only change)

Executing M6.4 made the dashboard state a **falsehood**: M6.5 was still described
as "required M6.4 candidate-exposure artifacts are not present on disk:
candidate_exposure_roads.geojson, candidate_exposure_settlements.geojson", quoting
its on-disk blocker — while both files existed. `AGENTS.md` §16 makes honest state
presentation the dashboard's job, so this was fixed at the cause:

- **`src/floodmap/dashboard/workflow.py`** — new exported
  `blocker_prerequisites_present(blocker, *, project_root)`: re-checks the
  blocker's **own** recorded `missing_inputs`/`missing_layers` against its own
  `searched_directory`. When every recorded input now exists, the stage is reported
  as `IMPLEMENTED_NOT_EXECUTED` with a detail that says the blocker is stale and the
  stage still has not run, and the original reason stays attached to the report as
  history. Nothing is inferred about prerequisites the blocker never mentioned, and
  an empty `missing` list is never treated as "present".
- **`tests/test_dashboard_workflow.py`** — 9 new tests: stale blocker with present
  inputs → not blocked; one still-missing input → still blocked; blocker without
  recorded inputs → still blocked; the stale reason kept as history but not used as
  the current detail; and checks for relative, absolute, missing-list-empty and
  blank-name handling.

This does **not** claim M6.5 ran, does not synthesise a result, and does not weaken
any gate.

## 6. Limitations explicitly retained

1. **AOI provenance `UNVERIFIED`** — every count is relative to a project-defined
   corridor, not an official or judge-selected boundary. Verified unchanged.
2. **36.6281 % of the AOI (75.5090 km²) is unobserved** — it lies outside the
   delivered raster footprint and is `OUTSIDE_CANDIDATE_GRID`, **not** a
   `not_observed` class value. Nothing is said about it and it is never "clear".
3. **No confirmed-damage claim** — intersections are SAR change-candidate overlap
   (spatial exposure). Not flood extent, not damage, not impassability. 13 prohibited
   interpretations are enumerated in the authorisation record.
4. **Hubs are read but not assessed** (`layers_read_but_not_assessed: ["hubs"]`);
   no hub layer is written, no hub-level claim permitted.
5. **Intersection-threshold sensitivity is unmeasured** — the four rules (5 m
   sampling, 10 m line minimum, 1 pixel per building, single-pixel settlement) are
   fixed by config and were not varied.
6. **M6.21 absolute geolocation remains blocked** (criterion A: no independent
   reference, no precise orbit). Relative alignment (B, ≤ 2 px) is retained only as
   a provisional engineering regression guard, never as validated accuracy.
7. Plus the mask-level limits: no thermal-noise removal, no layover/shadow mask,
   restituted orbits; OSM completeness is OSM's; 25 km-buffer road request omits
   `residential`/`service`; settlement verdicts are single-pixel.

**Outstanding owner action:** the authorisation record's signatory is recorded as
the **role** `project owner`; the personal name is **not** recorded and was not
invented. The checker surfaces this as `WARN` on every run.
